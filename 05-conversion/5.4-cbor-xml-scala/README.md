# 5.4. CBOR Diagnostic Notation → XML (Scala)

## Постановка

Преобразовать данные, записанные в диагностической нотации CBOR (RFC 8949, раздел 8; RFC 8610, приложение G), в XML-документ.

**Поддерживаемые элементы нотации:**

- целые числа (в том числе отрицательные и большие), числа с плавающей точкой, `NaN`, `Infinity`, `-Infinity`;
- текстовые строки `"..."` с escape-последовательностями;
- байтовые строки `h'0aff'`, `b64'...'`;
- массивы `[1, 2, 3]` и словари `{ключ: значение}` (ключом может быть любое значение);
- массивы и словари неопределённой длины `[_ ...]`, `{_ ...}`;
- `true`, `false`, `null`, `undefined`, `simple(n)`;
- теги `n(значение)`, например `1(1700000000)`.

**Реализация.** Собственный рекурсивный нисходящий парсер строит дерево значений, затем дерево преобразуется в XML с отступами. Специальные символы XML экранируются. Сторонние библиотеки не используются.

**Схема XML:** `<int>`, `<float>`, `<text>`, `<bytes encoding="hex">`, `<array>`, `<map>` с элементами `<entry><key>…</key><value>…</value></entry>`, `<bool>`, `<null/>`, `<undefined/>`, `<simple value="n"/>`, `<tag number="n">`.

**Обработка ошибок.** Синтаксическая ошибка с указанием строки и позиции, некорректные hex- и base64-данные.

## Реализация

- Дерево значений — перечисление `enum Value` с вариантами `IntV(BigInt)`, `FloatV`, `TextV`, `BytesV`, `ArrayV`, `MapV`, `BoolV`, `NullV`, `UndefinedV`, `SimpleV` и `TagV`. Целые числа хранятся в `BigInt`, поэтому значения вроде `18446744073709551615` не теряют точности.
- Класс `Parser` — рекурсивный нисходящий разбор. `value()` по первому символу выбирает разбор массива, словаря, строки, байтовой строки, числа или тега, либо слова (`true`, `false`, `null`, `undefined`, `NaN`, `Infinity`, `simple(n)`). Массивы, словари и теги разбирают вложенные значения рекурсивно, `_` после скобки означает неопределённую длину.
- Число, за которым идёт `(`, — это тег. Числа с точкой или экспонентой — `FloatV`, остальные — целые.
- `h'…'` переводится из шестнадцатеричной записи (пробелы внутри допускаются). `b64'…'` декодируется через `java.util.Base64`: недостающие `=` дописываются, поддерживается и вариант base64url.
- Комментарии нотации `/ … /` пропускаются. Несколько значений подряд (через запятую или пробел) становятся несколькими элементами внутри `<cbor>`.
- Генератор XML пишет простые значения одной строкой, а массивы, словари и составные ключи — с отступами. Символы `< > & " '` экранируются.
- При ошибке выводится номер строки и позиция символа. Если файл оборвался, позиция указывает сразу после последнего символа.

Используется только стандартная библиотека Scala и Java.

## Окружение

- Scala 3.3 или новее с Scala CLI и JDK 17 или новее (проверено на Scala 3.10.1, Scala CLI 1.18.0, Temurin JDK 21).
- Установка: [scala-lang.org/download](https://www.scala-lang.org/download/), macOS — `brew install scala`, Linux — через [Coursier](https://get-coursier.io): `cs setup`.

## Запуск

Из каталога задачи:

```bash
scala --power package --assembly --server=false src/CborToXml.scala -o bin/cbor2xml.jar -f
cat data/sample.diag
java -jar bin/cbor2xml.jar data/sample.diag
cat data/all_types.diag
java -jar bin/cbor2xml.jar data/all_types.diag
java -jar bin/cbor2xml.jar data/all_types.diag -o all_types.xml
xmllint --noout all_types.xml && echo "XML корректен"
```

Параметры:

- входной файл с диагностической нотацией CBOR;
- `-o файл` — записать XML в файл вместо консоли.

Первая команда собирает исполняемый jar со всеми зависимостями; `--server=false` отключает фоновый сервер сборки.

## Данные

| Файл                  | Содержимое                                                                                |
| --------------------- | ----------------------------------------------------------------------------------------- |
| `data/sample.diag`    | пример из постановки: словарь со строками, массивом, байтами и тегом                      |
| `data/all_types.diag` | все поддерживаемые виды значений, неопределённая длина, теги, составной ключ, комментарий |
| `data/bad.diag`       | незакрытый массив                                                                         |
| `data/bad_hex.diag`   | некорректные hex-данные                                                                   |
