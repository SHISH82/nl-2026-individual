## 1. Многопоточность

### 1.1. Параллельное вычисление матрицы расстояний Хэмминга (Rust)

**Постановка.** Дан набор из N строк одинаковой длины. Расстоянием Хэмминга между двумя строками называется количество позиций, в которых символы этих строк различаются. Требуется построить матрицу D размера N×N, где `D[i][j]` — расстояние Хэмминга между строками `i` и `j`.

**Входные данные.** Текстовый файл, в каждой непустой строке которого записано одно слово. Число потоков T задаётся аргументом командной строки (по умолчанию — число ядер процессора).

**Параллельная обработка.** Строки матрицы распределяются между T потоками. Каждый поток вычисляет только свои строки матрицы и записывает результат в свою, не пересекающуюся с другими, область памяти, поэтому синхронизация при записи не требуется. Главный поток дожидается завершения всех рабочих потоков и собирает результат. Используются только потоки стандартной библиотеки (`std::thread`).

**Выходные данные.** Матрица расстояний, выведенная в консоль или в файл в виде выровненной таблицы. Дополнительно выводится время вычисления в однопоточном и многопоточном режимах и проверка совпадения результатов.

**Обработка ошибок.** Если строки имеют разную длину, программа сообщает номер первой некорректной строки и завершается. Пустой файл и отсутствие файла также обрабатываются с выводом сообщения.

### 1.2. Параллельная медианная фильтрация числового сигнала (Ada)

**Постановка.** Дан числовой сигнал — последовательность вещественных чисел `x[1..n]`. Медианный фильтр с нечётным размером окна W заменяет каждое значение `x[i]` медианой значений в окне `x[i-k..i+k]`, где `k = (W-1)/2`. На границах сигнала недостающие значения заменяются крайним значением сигнала.

**Входные данные.** Текстовый файл с числами (через пробелы или переводы строк). Размер окна W и число задач T передаются аргументами командной строки.

**Параллельная обработка.** Сигнал делится на T непрерывных отрезков. Каждый отрезок обрабатывается отдельной задачей Ada (`task type`). Задачи читают общий входной массив и записывают результат каждая в свой диапазон выходного массива. Главная программа дожидается завершения всех задач.

**Выходные данные.** Отфильтрованный сигнал в консоль или в файл; проверка совпадения с результатом последовательной фильтрации; время работы.

**Обработка ошибок.** Чётный или неположительный размер окна, нечисловые значения во входном файле, пустой сигнал.

### 1.3. Параллельный поиск локальных максимумов матрицы (Julia)

**Постановка.** Дана числовая матрица размера M×N. Элемент называется локальным максимумом, если он строго больше всех своих соседей (до 8 соседей по горизонтали, вертикали и диагоналям; у элементов на границе соседей меньше). Требуется найти все локальные максимумы.

**Входные данные.** Текстовый файл: каждая строка файла — строка матрицы, числа разделены пробелами. Число потоков задаётся при запуске Julia (`julia -t T`).

**Параллельная обработка.** Строки матрицы распределяются между потоками (`Threads.@spawn`). Каждый поток собирает найденные максимумы в собственный локальный список, после завершения всех потоков списки объединяются и сортируются. Общий список во время работы потоков не изменяется, поэтому гонок данных нет.

**Выходные данные.** Количество локальных максимумов и их список в виде `(строка, столбец) = значение`; время работы в однопоточном и многопоточном режимах.

**Обработка ошибок.** Строки разной длины, нечисловые значения, пустая матрица.

### 1.4. Параллельное построение матрицы совместной встречаемости слов (D)

**Постановка.** Дан текст. Словом считается непрерывная последовательность букв (латиница и кириллица), регистр не учитывается. Два слова встречаются совместно, если расстояние между их позициями в тексте не превышает K (размер окна), при этом пара слова с самим собой в той же позиции не учитывается. Требуется построить симметричную матрицу совместной встречаемости размера V×V, где V — число различных слов, а элемент `C[a][b]` равен числу совместных появлений слов `a` и `b`.

**Входные данные.** Текстовый файл; размер окна K и число потоков T — аргументы командной строки.

**Параллельная обработка.** Последовательность слов делится на T частей. Каждый поток считает пары, начинающиеся в его части (окно может заходить в соседнюю часть только на чтение), и накапливает результат в собственном ассоциативном массиве. После завершения потоков частичные результаты объединяются. Используется `std.parallelism` или `core.thread` из стандартной библиотеки.

**Выходные данные.** Матрица (словарь отсортирован по алфавиту) записывается в файл в виде таблицы; в консоль выводятся N самых частых пар и время работы.

**Обработка ошибок.** Отсутствие файла, текст без слов, некорректные значения K и T.

## 2. Алгоритмическая задача

### 2.1. Рекурсивная генерация разбиений множества (Haskell)

**Постановка.** Дано конечное множество элементов. Разбиением множества называется представление его в виде объединения непустых попарно непересекающихся подмножеств (блоков). Требуется сгенерировать все разбиения множества.

**Алгоритм.** Рекурсия по элементам: разбиения множества `{x} ∪ S` получаются из каждого разбиения множества `S` либо добавлением `x` в один из существующих блоков, либо добавлением `x` отдельным новым блоком. База рекурсии — пустое множество с единственным пустым разбиением.

**Входные данные.** Элементы множества вводятся с консоли через пробел (или число n — тогда множество `{1..n}`). Необязательный параметр k — выводить только разбиения ровно на k блоков.

**Выходные данные.** Все разбиения, по одному на строку, и их количество (число Белла `B(n)`, а при заданном k — число Стирлинга второго рода `S(n, k)`).

**Обработка ошибок.** Повторяющиеся элементы, некорректное k.

### 2.2. Решение задачи о размене монет через рекурсию (Prolog)

**Постановка.** Дана сумма S и набор номиналов монет (каждый номинал доступен в неограниченном количестве). Требуется:
1. найти количество способов разменять сумму S (способы, отличающиеся только порядком монет, считаются одинаковыми);
2. вывести все способы размена;
3. найти способ с минимальным количеством монет.

**Алгоритм.** Рекурсивное отношение: число способов разменять S монетами `[C | Cs]` равно сумме числа способов разменять `S - C` теми же монетами (монета C используется) и числа способов разменять S монетами `Cs` (монета C больше не используется). База: `S = 0` — один способ; `S < 0` или пустой набор — ноль способов.

**Входные данные.** Сумма и список номиналов вводятся с консоли.

**Выходные данные.** Количество способов, список всех способов, минимальный размен. Если размен невозможен, выводится соответствующее сообщение.

### 2.3. Рекурсивная генерация правильных скобочных последовательностей (Scheme)

**Постановка.** Дано число n. Требуется сгенерировать все правильные скобочные последовательности из n пар круглых скобок в лексикографическом порядке (`(` < `)`). Дополнительно — рекурсивная проверка произвольной строки на правильность скобочной последовательности.

**Алгоритм.** Рекурсивная функция строит последовательность посимвольно, отслеживая число открытых и закрытых скобок: открывающую скобку можно поставить, пока их меньше n; закрывающую — пока закрытых меньше, чем открытых.

**Входные данные.** Число n (режим генерации) или строка (режим проверки) с консоли.

**Выходные данные.** Все последовательности и их количество (число Каталана `C(n)`); в режиме проверки — результат и позиция первой ошибки.

### 2.4. Рекурсивное восстановление бинарного дерева по результатам обходов (OCaml)

**Постановка.** Даны результаты прямого (preorder) и симметричного (inorder) обходов бинарного дерева с уникальными ключами. Требуется восстановить дерево. Дополнительно поддерживается пара «симметричный + обратный (postorder) обход».

**Алгоритм.** Первый элемент прямого обхода — корень. Его позиция в симметричном обходе делит симметричный обход на левое и правое поддеревья; соответствующие части прямого обхода определяются по размерам поддеревьев. Поддеревья восстанавливаются рекурсивно.

**Входные данные.** Два обхода — две строки с консоли или из файла.

**Выходные данные.** Дерево в наглядном текстовом виде, а также обратный обход и обход в ширину для проверки.

**Обработка ошибок.** Разная длина обходов, разные наборы элементов, повторяющиеся ключи, несогласованные обходы.

## 3. Ввод/вывод в консоль/файл

### 3.1. Нумерация строк текстового файла (Perl)

**Постановка.** Программа читает текстовый файл (или стандартный ввод, если файл не указан) и выводит его строки с номерами.

**Параметры командной строки:**
- начальный номер (по умолчанию 1) и шаг нумерации (по умолчанию 1);
- ширина поля номера и разделитель между номером и строкой;
- режим пропуска пустых строк (пустые строки выводятся, но не нумеруются);
- имя выходного файла (по умолчанию — вывод в консоль).

**Выходные данные.** Пронумерованный текст; в консоль — количество обработанных и пронумерованных строк.

**Обработка ошибок.** Отсутствующий или недоступный для чтения файл, некорректные значения параметров.

### 3.2. Создание и применение текстового патча (Nim)

**Постановка.** Программа работает в двух режимах:
1. `diff old.txt new.txt` — построчно сравнивает два файла и создаёт патч;
2. `apply old.txt file.patch` — применяет патч к исходному файлу и получает новую версию.

**Алгоритм.** Различия вычисляются через наибольшую общую подпоследовательность строк (динамическое программирование). Патч записывается в формате, близком к unified diff: блоки изменений с заголовком `@@ -a,b +c,d @@`, строки контекста начинаются с пробела, удалённые — с `-`, добавленные — с `+`. Число строк контекста задаётся параметром (по умолчанию 3).

**Выходные данные.** Файл патча (режим `diff`) или новый файл (режим `apply`); в консоль — число добавленных и удалённых строк.

**Обработка ошибок.** При применении проверяется совпадение строк контекста и удаляемых строк; при несовпадении выводится номер строки и патч не применяется. Некорректный формат патча.

**Проверка.** Для любой пары файлов `apply(old, diff(old, new)) = new`.

### 3.3. Объединение двух файлов с чередованием строк (Lua)

**Постановка.** Даны два текстовых файла. Требуется сформировать новый файл, в котором строки исходных файлов чередуются: строка первого, строка второго, строка первого и т. д. Когда один из файлов заканчивается, оставшиеся строки другого дописываются в конец.

**Параметры:** размеры блоков (m строк из первого файла, n строк из второго, по умолчанию 1 и 1), имя выходного файла (по умолчанию — вывод в консоль).

**Выходные данные.** Объединённый текст; в консоль — сколько строк взято из каждого файла.

**Обработка ошибок.** Отсутствующие файлы, некорректные размеры блоков, совпадение выходного файла с одним из входных.

### 3.4. Удаление повторяющихся строк из файла (Common Lisp)

**Постановка.** Программа читает текстовый файл и удаляет повторяющиеся строки. В отличие от утилиты `uniq`, входной файл не обязан быть отсортирован.

**Режимы:**
- удаление всех повторов с сохранением первого вхождения и исходного порядка строк (хеш-таблица);
- удаление только подряд идущих повторов.

**Параметры:** игнорирование регистра, игнорирование пробелов в начале и конце строки, имя выходного файла (по умолчанию — вывод в консоль), вывод частоты повторов.

**Выходные данные.** Текст без повторов; в консоль — количество исходных, оставшихся и удалённых строк.

**Обработка ошибок.** Отсутствующий файл, неизвестные параметры.

## 4. Клиент-серверное взаимодействие

Во всех задачах этой темы реализуются и сервер, и консольный клиент на одном языке. Взаимодействие идёт по TCP через средства стандартной библиотеки. Сервер обслуживает нескольких клиентов одновременно. Порт задаётся аргументом командной строки.

### 4.1. Сервер для проверки числа на простоту (Erlang)

**Постановка.** Клиент отправляет серверу целые числа, сервер для каждого числа определяет, является ли оно простым.

**Протокол (текстовый, построчный):**
- запрос — целое число;
- ответ `PRIME` — число простое;
- ответ `COMPOSITE d` — число составное, `d` — наименьший нетривиальный делитель;
- ответ `NEITHER` — для чисел 0 и 1;
- ответ `ERROR <описание>` — некорректный ввод (не число, отрицательное число);
- команда `QUIT` завершает сеанс.

**Алгоритм.** Проверка делителей вида `6k ± 1` до квадратного корня из числа; для больших чисел — детерминированный тест Миллера — Рабина.

**Реализация.** Сервер на `gen_tcp`, для каждого клиента создаётся отдельный процесс Erlang. Клиент читает числа с консоли, отправляет их и выводит ответы.

### 4.2. Сервер сравнения двух JSON-документов (Groovy)

**Постановка.** Клиент отправляет серверу два JSON-документа, сервер сравнивает их и возвращает список различий.

**Протокол.** Клиент читает два JSON-файла, сериализует каждый в одну строку и отправляет две строки подряд. Сервер возвращает строки с различиями и завершающую строку `END`. Если документы совпадают, возвращается `EQUAL`.

**Сравнение.** Выполняется рекурсивно по структуре документов. Для каждого различия указывается путь в формате `$.поле[индекс]`:
- `CHANGED $.user.name: "Ann" -> "Anna"`;
- `ADDED $.tags[2]: "new"`;
- `REMOVED $.age`;
- `TYPE $.id: number -> string`.

Порядок ключей в объектах не учитывается, массивы сравниваются поэлементно по индексам.

**Реализация.** Разбор JSON выполняется собственным рекурсивным парсером без сторонних библиотек. Сервер на `java.net.ServerSocket`, для каждого клиента — отдельный поток.

**Обработка ошибок.** Синтаксическая ошибка в JSON — ответ `ERROR` с указанием документа и позиции.

### 4.3. Сервер для конвертации единиц измерения (Kotlin)

**Постановка.** Клиент отправляет запросы на перевод значения из одной единицы измерения в другую, сервер возвращает результат.

**Категории единиц:**
- длина: `mm`, `cm`, `m`, `km`, `in`, `ft`, `mi`;
- масса: `g`, `kg`, `t`, `oz`, `lb`;
- температура: `C`, `F`, `K`;
- время: `s`, `min`, `h`, `day`.

**Протокол:**
- `CONVERT <значение> <из> <в>` → `OK <результат> <в>`;
- `LIST` → список поддерживаемых единиц по категориям;
- `QUIT` — завершение сеанса;
- при ошибке → `ERROR <описание>` (неизвестная единица, единицы из разных категорий, некорректное число, температура ниже абсолютного нуля).

**Реализация.** Линейные величины переводятся через базовую единицу категории, температура — по формулам. Сервер на `java.net.ServerSocket`, каждый клиент обслуживается в отдельном потоке.

### 4.4. Сервер совместных таймеров обратного отсчёта (Elixir)

**Постановка.** Сервер хранит именованные таймеры обратного отсчёта, общие для всех подключённых клиентов. Любой клиент может создать таймер, другие клиенты могут подписаться на него, управлять им и получить уведомление об окончании отсчёта.

**Протокол:**
- `CREATE <имя> <секунды>` — создать и запустить таймер (создатель подписывается автоматически);
- `JOIN <имя>` — подписаться на таймер;
- `LEAVE <имя>` — отписаться;
- `STATUS <имя>` — оставшееся время и состояние;
- `PAUSE <имя>` / `RESUME <имя>` — приостановить и продолжить;
- `CANCEL <имя>` — отменить таймер (подписчики получают `CANCELLED <имя>`);
- `LIST` — список всех таймеров;
- по окончании отсчёта сервер рассылает всем подписчикам `DONE <имя>`.

**Реализация.** Каждый таймер — отдельный процесс, отсчёт через `Process.send_after`. Сервер на `:gen_tcp`, каждый клиент обслуживается своим процессом. Клиент принимает асинхронные уведомления от сервера одновременно с вводом команд.

**Обработка ошибок.** Повторное имя таймера, несуществующий таймер, некорректное время, отключение клиента (подписка снимается автоматически).

## 5. Конвертация данных из одного формата в другой

### 5.1. TSV → текстовая таблица (Ruby)

**Постановка.** Преобразовать файл в формате TSV (значения разделены символом табуляции, первая строка — заголовок) в текстовую таблицу с рамками для вывода в консоль или файл.

**Требования:**
- ширина столбцов вычисляется по самому длинному значению с учётом Unicode-символов;
- числа выравниваются по правому краю, текст — по левому;
- строки с меньшим числом полей дополняются пустыми ячейками;
- поддерживаются escape-последовательности `\t`, `\n`, `\\` внутри полей;
- стиль рамки: ASCII (`+`, `-`, `|`) или Unicode (`┌`, `─`, `┼`, `│`).

**Обработка ошибок.** Пустой файл, строки с большим числом полей, чем в заголовке (выводится предупреждение с номером строки).

### 5.2. PPM → PGM (Swift)

**Постановка.** Преобразовать цветное изображение в формате PPM в полутоновое изображение в формате PGM.

**Требования:**
- поддержка текстового (`P3`) и двоичного (`P6`) PPM; выход — текстовый (`P2`) или двоичный (`P5`) PGM;
- собственный разбор заголовка: комментарии `#`, произвольные пробельные символы, `maxval` до 65535 (1 или 2 байта на канал);
- способы вычисления яркости: взвешенная сумма по ITU-R BT.601 `Y = 0.299·R + 0.587·G + 0.114·B` (по умолчанию), среднее арифметическое, `(max + min) / 2`;
- используется только `Foundation` для чтения и записи файлов.

**Выходные данные.** PGM-файл; в консоль — размеры изображения и формат.

**Обработка ошибок.** Неверная сигнатура, некорректный заголовок, недостаточное количество данных пикселей, значения больше `maxval`.

### 5.3. Markdown-таблица → LaTeX-таблица (F#)

**Постановка.** Преобразовать таблицы в формате Markdown (GitHub Flavored Markdown) в таблицы LaTeX (окружение `tabular`).

**Требования:**
- разбор строки-разделителя с выравниванием столбцов: `:---` → `l`, `:---:` → `c`, `---:` → `r`;
- крайние символы `|` в строках необязательны, экранированный `\|` внутри ячейки не является разделителем;
- экранирование специальных символов LaTeX: `& % $ # _ { } ~ ^ \`;
- преобразование встроенной разметки: `**текст**` → `\textbf{текст}`, `*текст*` → `\textit{текст}`, `` `код` `` → `\texttt{код}`;
- заголовок таблицы выделяется жирным, строки разделяются `\hline`;
- по параметру таблица оборачивается в окружение `table` с подписью `\caption`;
- если в файле несколько таблиц, преобразуется каждая.

**Обработка ошибок.** Отсутствие строки-разделителя, разное количество ячеек в строках (с указанием номера строки).

### 5.4. CBOR Diagnostic Notation → XML (Scala)

**Постановка.** Преобразовать данные, записанные в диагностической нотации CBOR (RFC 8949, раздел 8; RFC 8610, приложение G), в XML-документ.

**Поддерживаемые элементы нотации:**
- целые числа (в том числе отрицательные и большие), числа с плавающей точкой, `NaN`, `Infinity`, `-Infinity`;
- текстовые строки `"..."` с escape-последовательностями;
- байтовые строки `h'0aff'`, `b64'...'`;
- массивы `[1, 2, 3]` и словари `{ключ: значение}` (ключом может быть любое значение);
- массивы и словари неопределённой длины `[_ ...]`, `{_ ...}`;
- `true`, `false`, `null`, `undefined`, `simple(n)`;
- теги `n(значение)`, например `1(1700000000)`.

**Реализация.** Собственный рекурсивный нисходящий парсер строит дерево значений, затем дерево преобразуется в XML с отступами. Специальные символы XML экранируются. Сторонние библиотеки не используются.

**Схема XML:** `<int>`, `<float>`, `<text>`, `<bytes encoding="hex">`, `<array>`, `<map>` с элементами `<entry><key>…</key><value>…</value></entry>`, `<bool>`, `<null/>`, `<undefined/>`, `<simple value="n"/>`, `<tag number="n">`.

**Обработка ошибок.** Синтаксическая ошибка с указанием строки и позиции, некорректные hex- и base64-данные.
