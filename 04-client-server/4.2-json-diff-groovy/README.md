# 4.2. Сервер сравнения двух JSON-документов (Groovy)

## Постановка

Клиент отправляет серверу два JSON-документа, сервер сравнивает их и возвращает список различий. Сервер и консольный клиент реализованы на одном языке, взаимодействие идёт по TCP, сервер обслуживает нескольких клиентов одновременно, порт задаётся аргументом командной строки.

**Протокол.** Клиент читает два JSON-файла, сериализует каждый в одну строку и отправляет две строки подряд. Сервер возвращает строки с различиями и завершающую строку `END`. Если документы совпадают, возвращается `EQUAL`.

**Сравнение.** Выполняется рекурсивно по структуре документов. Для каждого различия указывается путь в формате `$.поле[индекс]`:

- `CHANGED $.user.name: "Ann" -> "Anna"`;
- `ADDED $.tags[2]: "new"`;
- `REMOVED $.age`;
- `TYPE $.id: number -> string`.

Порядок ключей в объектах не учитывается, массивы сравниваются поэлементно по индексам.

**Реализация.** Разбор JSON выполняется собственным рекурсивным парсером без сторонних библиотек. Сервер на `java.net.ServerSocket`, для каждого клиента — отдельный поток.

**Обработка ошибок.** Синтаксическая ошибка в JSON — ответ `ERROR` с указанием документа и позиции.

## Реализация

- Класс `Parser` — рекурсивный нисходящий разбор JSON: `parseValue` выбирает разбор объекта, массива, строки (с escape-последовательностями и `\uXXXX`), числа, `true`, `false` или `null`. Объекты становятся `LinkedHashMap`, массивы — списками, числа — `BigDecimal`. При ошибке сообщается позиция символа.
- `toJson` записывает разобранный документ обратно в одну строку. Так клиент отправляет многострочный файл одной строкой протокола.
- `diff(a, b, path, out)` — рекурсивное сравнение:
  - если типы разные — `TYPE`;
  - у объектов ключи сравниваются по наличию (`REMOVED`, `ADDED`), а общие поля — рекурсивно;
  - массивы сравниваются по индексам;
  - числа сравниваются через `compareTo`, поэтому `1` и `1.0` равны;
  - остальные значения сравниваются на равенство (`CHANGED`).
- Сервер (`server <порт>`) принимает подключения на `ServerSocket` и для каждого клиента запускает отдельный поток (`Thread.start`). Поток читает две строки, отвечает различиями, затем `END`, и пишет итог в журнал сервера.
- Клиент (`client <хост> <порт> <файл1> <файл2>`) сначала сам проверяет оба файла, отправляет документы и печатает ответ сервера до строки `END`.
- Все потоки ввода и вывода работают в кодировке UTF-8.

Используется только стандартная библиотека Groovy/Java. Встроенный в Groovy модуль работы с JSON не используется.

## Окружение

- Groovy 4 или новее и JDK 17 или новее (проверено на Groovy 5.1.3 и Temurin JDK 21).
- Установка: [groovy.apache.org/download.html](https://groovy.apache.org/download.html), macOS — `brew install groovy`, Linux — через [SDKMAN](https://sdkman.io): `sdk install groovy`.

## Запуск

Из каталога задачи:

```bash
cat data/a.json
cat data/b.json
groovy src/jsondiff.groovy server 5002 > server.log &
groovy src/jsondiff.groovy client localhost 5002 data/a.json data/b.json
cat data/shop_v1.json
cat data/shop_v2.json
groovy src/jsondiff.groovy client localhost 5002 data/shop_v1.json data/shop_v2.json
cat data/order1.json
cat data/order2.json
groovy src/jsondiff.groovy client localhost 5002 data/order1.json data/order2.json
(groovy src/jsondiff.groovy client localhost 5002 data/a.json data/b.json & groovy src/jsondiff.groovy client localhost 5002 data/order1.json data/order2.json & wait)
cat server.log
```

Параметры:

- `server <порт>` — запустить сервер;
- `client <хост> <порт> <файл1.json> <файл2.json>` — сравнить два файла на сервере;
- остановить сервер: `kill %1` в том же терминале или Ctrl+C, если сервер запущен без `&`.

## Данные

| Файл                                     | Содержимое                                                                   |
| ---------------------------------------- | ---------------------------------------------------------------------------- |
| `data/a.json`, `data/b.json`             | пример из постановки: изменённое, удалённое и добавленное поле               |
| `data/shop_v1.json`, `data/shop_v2.json` | вложенные объекты и массивы: изменения значений, типа, добавления и удаления |
| `data/order1.json`, `data/order2.json`   | одинаковые документы с другим порядком ключей, `1` и `1.0`, `Ж` и `Ж`        |
| `data/broken.json`                       | документ с синтаксической ошибкой                                            |
